# v0.48.48 — Convierte tarjeta Aris en acordeón con header persistente

## Versión base (contexto)

- **v0.48.47** — expande contenido útil en Home según altura disponible; input Aris fijo; cuerpo Aris (header + mensaje) dentro del `ListView` y dock de input como segunda pieza visual debajo.
- Se mantiene: fecha fija, scroll estable, retícula `HomeCardTheme`, adaptación de HOY por altura, input siempre visible.

## Problema detectado

La ficha de Aris se percibía como **dos módulos pegados**: tarjeta superior (header + mensaje) en scroll y barra de input fija con decoración distinta (`arisCardBodyDecoration` + `arisCardInputDockDecoration`). Al colapsar scroll no quedaba claro un mínimo estructural **header + input** en una sola pieza.

## Objetivo del cambio

- Una sola tarjeta tipo **acordeón**: carcasa unitaria, header persistente, cuerpo del mensaje colapsable, input integrado.
- **Expandida:** header + mensaje + input.
- **Colapsada:** header + input (solo desaparece el cuerpo del mensaje).
- Prioridad: robustez y snap suave (`AnimatedSize`), sin animaciones frágiles.

## Decisión técnica aplicada

1. **`HomeArisDockCard`** — widget unificado con `HomeCardTheme.cardDecoration` (radio completo), header, `AnimatedSize` para el bloque mensaje y input en la misma columna.
2. **`HomeScreen`** — Aris sale del `ListView`; el dock va fijo al pie del `Column`. El scroll solo lleva saludo + HOY + separación inferior.
3. **Estado acordeón** — `_arisMessageExpanded`: `true` mientras el borde inferior de HOY está dentro del viewport del scroll (`todayBottom > 0`); `false` cuando HOY sale del viewport (misma señal que antes usaba el tope de scroll sobre Aris, sin `_preventArisScrollPastTop`).
4. **`HomeSummaryLayoutMetrics`** — el chrome del presupuesto de altura ya no incluye Aris (está fuera del área scrollable del `ListView`).

| Colapsado (`messageExpanded: false`) | Header ARIS + input |

| Transición | `AnimatedSize` 200 ms, `Curves.easeOutCubic` |

## Criterios de aceptación

- [x] El input de Aris sigue fijo y siempre visible
- [x] El header de Aris sigue visible cuando la tarjeta se colapsa
- [x] El cuerpo del mensaje es la única parte que se colapsa
- [x] La tarjeta se lee como una sola pieza tipo acordeón
- [x] La Home sigue estable (sin tope de scroll sobre Aris en lista)
- [x] El scroll no se rompe
- [x] `dart analyze` sin incidencias

## Resultado esperado

- Identidad de tarjeta Aris siempre reconocible (header + input como mínimo).
