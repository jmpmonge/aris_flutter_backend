# v0.48.47 — Expande contenido útil en Home según altura disponible

## Versión base (contexto)

- **v0.48.46** — fecha fija, input Aris fijo, ficha Aris scrollable, tope de sobre-scroll superior, sin padding inferior inflado en el `ListView`.
- Se mantiene: input fijo, scroll estable, retícula y continuidad visual Aris (cuerpo + dock).

## Problema detectado

En pantallas altas, el bloque HOY mostraba siempre 2 eventos / 3 tareas / 1 mail y quedaba **espacio vertical útil sin usar** entre el resumen y la ficha de Aris, como aire muerto en lugar de más información.

## Objetivo funcional

- **Mínimo base** (pantalla normal): Agenda **2**, Tareas **3**, Mail **1**.
- Con **más altura** en el viewport del scroll, añadir elementos reales en orden cíclico:
  1. Agenda +1
  2. Tareas +1
  3. Mail +1
  4. Agenda +1 …
- Sin padding ni `SizedBox` artificiales para rellenar hueco.

## Decisión técnica aplicada

1. **`LayoutBuilder`** en el `Expanded` de Inicio: obtiene `constraints.maxHeight` del área scrollable real.
2. **`HomeSummaryLayoutMetrics`**: estima altura de la tarjeta HOY y del chrome fijo (saludo, Aris compacto, separaciones) con constantes alineadas a `TodaySummaryCard` y `HomeArisReplyCard`.
3. **`HomeVisibleCounts.forListViewport`**: resta chrome, compara con altura base 2/3/1 y reparte slots extra en ciclo **agenda → tareas → mail**, solo si hay datos disponibles.
4. **`TodaySummaryCard`**: parámetros `maxAgendaItems`, `maxTaskItems`, `maxMailItems`; catálogo mail demo = **21** entradas (mismo tope que `_demoMailTotalCount`), no solo 6.
