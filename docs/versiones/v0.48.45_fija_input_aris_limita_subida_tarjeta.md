## Problema detectado

En Home, la tarjeta de Aris e el input vivían en el mismo bloque dentro del `ListView`. Al hacer scroll:

- el input se desplazaba con el contenido y dejaba de estar siempre accesible;
- en algunos desplazamientos podía aparecer un hueco superior anómalo (más aire del ritmo estándar entre tarjetas) y romper la secuencia visual HOY → Aris.

## Objetivo

1. **Input de Aris fijo** y siempre visible (zona inferior de Inicio, encima de la barra de navegación).
2. **Tarjeta de Aris (cabecera + mensaje) scrollable** como el resto del contenido.
3. **Límite superior**: al subir con el scroll, la tarjeta no puede dejar por encima un hueco mayor que `AppSpacing.homeSectionGapMax` (16 px).

## Decisión de layout

```
┌─────────────────────────────┐
│  ListView (scroll)          │
│  · fecha / saludo / clima   │
│  · TodaySummaryCard         │
│  · gap 16 px                │
│  · HomeArisReplyCard (body) │
├─────────────────────────────┤
│  HomeArisFixedInputBar      │  ← fijo (no scroll)
└─────────────────────────────┘
│  bottom nav                 │
```

- Separación HOY → Aris en lista: `homeSectionGapMax` (16 px).
- `ScrollController` + medición del borde superior de la tarjeta: si el hueco visible sobre la tarjeta supera 16 px, se ajusta el offset (`jumpTo`) para mantener el ritmo vertical.
- Sin `SliverFillRemaining` ni padding inferior inflado que genere vacío artificial.
