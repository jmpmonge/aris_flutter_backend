# v0.49.21 — Revisión transversal de consistencia visual y de interacción

## 1. Contexto

Tras varias iteraciones en Home, Calendario, Notas y Tareas, se realiza una revisión transversal para comprobar si el sistema ya se percibe como una familia coherente antes de abrir Perfil.

Revisión realizada sobre código en `aris_flutter_v0.22` (sin cambios de implementación en esta pasada).

## 2. Objetivo

- Revisar consistencia entre pantallas.
- Detectar incoherencias reales.
- Evitar cambios grandes prematuros.
- Priorizar las siguientes correcciones del sistema.

## 3. Áreas revisadas

- headers
- input inferior de Aris (`HomeArisFixedInputBar`)
- manual vs Aris
- sheets / páginas inside
- tarjetas / listas
- color y acento

## 4. Resultado

### Consistente

- **Input inferior compartido:** Home, Calendario, Notas y Tareas usan el mismo `HomeArisFixedInputBar` (altura `dockHeight`, radio 22, padding horizontal `homePageMarginH`, mic/enviar). Hints contextuales distintos pero coherentes.
- **Separación manual / Aris en pestañas secundarias:** Calendario, Notas y Tareas tienen `+` en `AppHeader` (manual) e input fijo (Aris). FAB del shell oculto en esas pestañas (solo visible en Perfil).
- **Headers de pestaña:** Calendario, Notas y Tareas comparten `AppHeader` (`headlineMedium`, sin subtítulo técnico, `IconButton.filledTonal` con `Icons.add_rounded`).
- **Padding de lista respecto al dock:** Calendario, Notas y Tareas usan `HomeArisFixedInputBar.dockHeight + homeScrollBottomBreathing`.
- **Rótulos de sección en listas:** Notas («Recientes») y Tareas (buckets HOY/PRÓXIMAS/…) comparten estilo `labelSmall` primary, letter-spacing elevado.
- **Acento naranja acotado:** Solo en metadatos activos del editor manual de Tareas (`TaskManualEditorAccent`); CTA de creación usa color primary del tema. No contamina Home/Calendario/Notas.
- **Home como excepción razonable:** Sin `AppHeader` genérico; cabecera fecha + saludo + bloque HOY + tarjeta Aris en scroll. Encaja con su rol de hub, no rompe el sistema de pestañas.

### A corregir

1. **Familia de entrada manual dispareja (impacto alto)**  
   - **Notas:** lienzo en `MaterialPageRoute` (página inside, flecha atrás).  
   - **Tareas:** sheet alto ~68 % desde abajo (`showModalBottomSheet`).  
   - **Calendario:** bottom sheet formulario clásico (`LocalActionFormSheet.showEventForm` + `FormSectionTitle` + dos botones).  
   Las tres pantallas cumplen «manual arriba / Aris abajo», pero no se sienten como la misma familia de editor.

2. **Calendario: copy y tono del formulario manual aún mezclan Aris (impacto medio)**  
   El `+` abre `_EventFormBody` con cabecera **«Nuevo evento con Aris»** y campos tipo formulario administrativo. Contradice la regla ya aplicada en Notas/Tareas: el manual no debe parecer canal conversacional.

3. **Home: doble superficie de interacción con Aris (impacto medio-bajo)**  
   Inicio tiene `HomeArisReplyCard` (bloque en scroll) **y** `HomeArisFixedInputBar` (dock). Las otras pestañas solo tienen el dock. Funcionalmente correcto; a nivel de sistema puede percibirse como doble patrón de «hablar con Aris» en la misma pantalla.

4. **Tarjetas de listado: dos lenguajes cercanos pero no unificados (impacto bajo)**  
   - Notas recientes: `AppCard` (Card del tema, radio `radiusLg`).  
   - Tareas: `CompactExpandableTaskTile` (Card plano, elevación 0, radio 14, borde outline).  
   Pertenecen al mismo universo oscuro Aris, pero no comparten el mismo tratamiento de contorno/sombra.

5. **Perfil conserva FAB azul de Aris (impacto bajo, fuera de alcance de esta revisión)**  
   En `app_navigation_shell`, el FAB solo aparece en pestaña Perfil. No contradice Calendario/Notas/Tareas, pero el sistema global aún tiene un tercer acceso a Aris solo ahí (documentar para cuando se abra Perfil).

### Prioridad sugerida

1. **Unificar entrada manual de Calendario** con el lenguaje ya validado en Tareas (sheet alto compacto) o, como mínimo, limpiar copy y quitar sensación «con Aris» del formulario del `+`.
2. **Decidir patrón único de dirección** para creación manual: sheet desde abajo (Tareas) vs página (Notas) — alinear o documentar criterio por tipo de contenido.
3. **Revisar Home** en una pasada dedicada: ¿mantener tarjeta Aris en scroll + dock o converger hacia solo dock como el resto?
4. **Afinar familia de tarjetas** (radio/sombra/borde) en una pasada pequeña transversal, sin igualar comportamientos (expansión vs tap a página).
5. **Perfil:** al diseñar la pantalla, resolver FAB vs input fijo para no reintroducir duplicidad.
